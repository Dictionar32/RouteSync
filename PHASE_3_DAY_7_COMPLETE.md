  // Write compiler-generated types
  const compilerTypesPath = path.join(options.output, 'types', 'compiler-generated.ts')
  await fs.ensureDir(path.dirname(compilerTypesPath))
  await fs.writeFile(compilerTypesPath, compilerOutput.code)

  console.log(`    - Types: ${compilerOutput.metadata.typeCount}`)
  console.log(`    - Interfaces: ${compilerOutput.metadata.interfaceCount}`)
  console.log(`    - LOC: ${compilerOutput.metadata.linesOfCode}`)
} catch (compilerError) {
  console.warn(`  [CompilerBridge] Warning: ${compilerError.message}`)
}

## 🔧 Technical Details

### Data Flow (Evidence-Based)

```
RouteManifest (CLI scan)
    ↓
CompilerBridge.manifestToSemanticTypes()
    ↓
SemanticTypesArtifact {
    typeId: 'SemanticTypes',
    types: SemanticType[],  // Array of ObjectTypes
    metadata: { ... }
}
    ↓
TypeScriptGeneratorPass.run([artifact])
    ↓
GeneratedTypeScriptArtifact {
    typeId: 'GeneratedTypeScript',
    code: string,           // Generated TypeScript
    imports: [],
    interfaces: [],
    generationMetadata: {
        typeCount: 5,
        interfaceCount: 5,
        linesOfCode: 69,
        warnings: []
    }
}
    ↓
fs.writeFile('types/compiler-generated.ts', code)
```

### Key Design Decisions

1. **Direct Pass Call vs PassManager**
   - **Chosen:** Direct pass.run() call
   - **Rationale:** Simpler, matches E2E test pattern, immediate access to artifact
   - **Alternative:** PassManager.execute() returns CompilationResult (requires state extraction)

2. **Parallel Execution**
   - **Strategy:** Run compiler path alongside existing generators
   - **Benefit:** Non-breaking change, easy comparison, safe rollback
   - **Output:** Both `compiler-generated.ts` (new) and `index.ts` (existing)

3. **Error Handling**
   - **Strategy:** Try-catch with warning + fallback
   - **Benefit:** Generation continues even if compiler path fails
   - **Logging:** Clear separation of compiler bridge logs

## 🐛 Known Issues & Limitations

### 1. Interface Naming
**Issue:** Generated interfaces have synthetic names (`Type1785966446949`)

**Cause:** `buildCodeFromTypes()` uses `Date.now()` for naming

**Impact:** Low - interfaces generated, but names not semantic

**Fix Needed:** Use actual model/resource names from manifest
```typescript
// Current:
const name = `Type${Date.now()}`

// Should be:
const name = model.name || resource.name
```

**Priority:** Medium (functional but not ideal)

### 2. Type Conversion
**Issue:** All properties currently map to `string`

**Cause:** Simple primitive type conversion in `sqlToSemanticType()`

**Impact:** Medium - loses type specificity (numbers, booleans, etc.)

**Fix Needed:** More sophisticated type mapping
```typescript
// Current: Everything becomes string
qty: string;
harga: string;

// Should be:
qty: number;
harga: number;
```

**Priority:** High (affects type safety)

### 3. Duplicate Interface Names
**Issue:** Multiple interfaces with same name

**Cause:** Same `Date.now()` timestamp for quick sequential generations

**Impact:** Medium - TypeScript compilation warning

**Fix Needed:** Include index or use model/resource name

**Priority:** Medium
