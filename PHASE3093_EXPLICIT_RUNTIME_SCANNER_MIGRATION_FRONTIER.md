# Phase 3093 — Explicit Runtime Scanner Migration Frontier

## Scope and integrity

This phase refreshes the repository-wide lexical frontier and anchors it to the actual PHP source-read runtime path. It does **not** claim a completed repository-wide export rewrite. The counts are lexical inventory, not AST-aware transformation results, so they are a migration estimate rather than proof that every candidate can be safely rewritten by a text substitution.

## Runtime path traced

`CLI scan/sync` → `manifest scan operation` → `controllerInvocationManifestComposition` → source discovery and reader → `PhpSourceDocumentReadResult.bindIdentity(...)` → identity-binding authority → source-read batch judgments → invocation semantic pipeline → manifest build/projection/validation → generator consumers.

The source-read result's generic `continueWith<Result>` was removed in Phase 3092 and replaced with `bindIdentity`, `bindCompleteResult`, and `bindBlockedResult`. The next unresolved boundary is batch continuation: source-read operation batches, identity-binding batches, and document-read batches still expose generic continuation-handler patterns. They must be migrated as a coordinated domain boundary, because the core upstream package must not import CLI manifest types merely to make a generic continuation disappear.

## Current lexical frontier

The generated `reports/PHASE3093_EXPLICIT_RUNTIME_SCANNER_MIGRATION_FRONTIER.json` inventories all TypeScript-family source files under `packages/core/src`, `packages/cli/src`, `packages/sdk/src`, and `packages/react/src` for exported function declarations, exported arrow constants, generic continuation signatures, and selected control-flow tokens.

The current measured inventory is:

- 2,244 TypeScript-family source files
- 523 `export function` declarations
- 344 exported arrow constants matching the current lexical pattern
- 867 export migration candidates in that narrow pattern
- 163 generic `continueWith` signatures
- 575 `switch`, 2,247 `if`, 259 nullish-coalescing, 827 `.map`, and 11 `.reduce` lexical occurrences

These figures do not include every possible arrow-function syntax, do not prove semantic ownership, and do not count every ternary/primitive occurrence. A TypeScript AST-based inventory is required before any repository-wide automated rewrite.

## Migration rules

1. Keep the PHP/Laravel source evidence, requested source identity, observed source identity, rejection evidence, provenance, and blockers intact.
2. Keep the deleted semantic relation foundation deleted: do not restore `relationMembership`, `relationalSequence`, or `semanticRelations`, and do not add kernel re-exports to them.
3. Move operations to the ADT that owns the domain meaning; do not create a new generic foundation or duplicate an existing source of truth.
4. Convert exports to `export const name: Interface = ...` only when a suitable explicit interface exists and the implementation preserves the existing contract. Do not fabricate a meaningless interface to satisfy syntax.
5. Do not mechanically remove `string`, `number`, `undefined`, `null`, `boolean`, arrays, branches, or iteration. First model the semantic distinctions as domain types; preserve legitimate scalar leaf values and syntax traversal needed to parse source.
6. Do not make the core package depend on CLI manifest types. Define explicit domain operations at the upstream boundary and keep manifest-specific terminal conversion in the CLI layer.
