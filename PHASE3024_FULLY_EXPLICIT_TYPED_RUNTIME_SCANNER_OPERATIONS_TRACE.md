# Phase 3024 — Fully Explicit Simplicity Typed Runtime Scanner Operations

## Scope and honesty boundary

This phase traces the real `upstream → CLI → manifest` runtime path and records the next domain-model migrations. It is a static source audit, not a successful TypeScript build or an end-to-end runtime test. The runtime implementation has not been broadly rewritten in this phase; the report distinguishes existing contracts from remaining primitive-model debt so a wrapper-only change is not misrepresented as completion.

## Runtime trace

1. `packages/cli/src/commands/scan.ts` / `sync.ts` consume the CLI manifest scan operation.
2. `packages/cli/src/manifestScanOperationInterface.ts` exposes `routeSyncCliManifestScanOperationFactory: RouteSyncCliManifestScanOperationFactoryInterface`; its `scan` operation delegates to `authority.compose(input)`.
3. `packages/cli/src/parsers/php/controllerInvocationManifestComposition.ts` composes through `input.continueToCanonicalization(...)`, then source-project canonicalization, controller-source discovery, source-document reading/identity binding, invocation semantic pipeline, inventory validation, and manifest preparation.
4. `packages/cli/src/parsers/php/controllerInvocationManifestCompositionInterface.ts` models complete and blocked terminal outcomes with `continueForDriftAudit`; the manifest-builder judgment is adapted through its own `continueWith` operation.
5. `packages/core/src/compiler/scanner/wiring/laravelRouteScanner.ts` calls `sourceObservation.continueToRouteScan(...)`. The ready source-observation variant owns source reads and forwards the read batch to the supplied continuation; the blocked variant preserves missing-file evidence and cannot produce a read plan.
6. Route declaration AST/evidence then flows through method judgment, declaration composition, authorization/resource/path judgments, route AST production, semantic flow projection, and a `LaravelRouteScanJudgment`. The CLI manifest path is a separate orchestration path, but shares the upstream typed-domain philosophy and source identity/provenance contracts.

## Model findings

### Already represented as operations

- CLI manifest scan is an interface-typed operation object, not an exported function declaration.
- Composition input owns `continueToCanonicalization` and carries source project identity plus route-selection intent.
- Manifest terminal judgments own `continueForDriftAudit` and preserve complete versus blocked/rejected distinctions.
- Laravel route source observation uses ready/blocked ADTs with domain-specific `continueToRouteScan`; the runtime scanner does not need to re-dispatch on the observation `kind`.

### Remaining primitive reasoning in the upstream model

- `packages/core/src/types/upstream/valueObjects.ts`: `StatementIndex = NumberValue`; `numberValue(value: number)` and `truthValue(value: boolean)` are still function-valued exports. These do not model statement order or truth judgment; they merely wrap primitive values.
- `packages/core/src/types/upstream/provenance.ts`: `SourceSpan.start` and `.end` are `NumberValue`, so the model does not distinguish source offset semantics from arbitrary numeric data.
- `packages/core/src/compiler/frontend/php/routeAst/phpControllerDataflowSourcePayloadEvidenceAdapter.ts`: statement ordering is generated by `let nextStatementIndex = 0` and `+= 1`, then wrapped as `NumberValue`. This is a concrete candidate to replace with a `StatementSequence` / `StatementIndex` domain operation, with the numeric ordinal kept only at the parser/serialization edge.
- `packages/core/src/types/upstream/names.ts`: model/route name constructors still accept raw `string`. A blanket primitive-wrapper conversion would only hide the string. Each name type needs explicit normalization/validation/identity semantics at the boundary and domain operations downstream.
- Raw offsets, file paths, source text and PHP AST values are expected at external parser/filesystem boundaries. The target is to keep them at those boundaries and prevent semantic decisions from being recomputed from primitive values deeper in the runtime.

## Recommended migration order

1. **Statement sequence first**: replace `StatementIndex = NumberValue` with a dedicated ADT and interface-backed operation object. Give the sequence domain-owned `first` / `successor` / ordering operations; update the PHP dataflow payload adapter and consumers as one migration. Keep raw parser ordinal conversion at the edge only. Do not introduce a generic callback visitor.
2. **Source positions second**: introduce distinct `SourceOffset` and `SourceSpan` operations such as range construction and containment/width semantics. Migrate all source-span producers and consumers together, including controller AST canonicalization and CLI PHP AST adapters. Keep parser offsets as boundary input, not semantic source-of-truth values.
3. **Domain names third**: trace each name type to its actual producers and consumers. Convert each factory to `export const name: NameOperationsInterface = Object.freeze({...})` with domain-specific operations; do not use a single generic string wrapper as the substitute for domain modeling.
4. **Truth/security judgments fourth**: replace `TruthValue` only where it is a real semantic judgment (for example, a route-security decision) with a closed domain ADT carrying its allowed continuation. Do not erase booleans returned by external libraries at their boundary.
5. **Syntax navigation fifth**: model token cursors, delimiter/nesting facts and statement sequencing as syntax-navigation data. Retain `switch`/AST-kind dispatch where it is the parser's exhaustive interpretation of a closed AST union; remove control-flow branches only when they are storing semantic knowledge that belongs in an ADT.
6. **After every slice**: trace upstream → CLI → manifest again; run typecheck, focused tests, and manifest integration tests; compare evidence/provenance, type facts and blocker inventories before/after. No relation foundation modules under `packages/core/src/semantic/relations/` may be restored.

## Laravel / TypeScript grounding

Laravel's official routing documentation defines route source conventions, route parameters, named routes and model binding. RouteSync should model the domain facts that affect those semantics instead of inferring them from generic strings deep in the pipeline. TypeScript interfaces define contracts/shapes, while discriminated unions model closed alternatives; an interface by itself does not make a model semantically rich. See the official references in the response accompanying this report.

## Verification

Run `node scripts/audits/audit-phase3024-fully-explicit-typed-runtime-scanner-operations.cjs` for the static checks. This report does **not** claim that primitive use, `??`, ternaries, `reduce`, arrays, or every `if/switch/while` has been eliminated. Those require scoped consumer tracing and compile/test verification; blanket deletion would risk loss of parser facts and evidence.
