# Phase 1654 — Invocation Semantic Model, Interface First

## Objective

Raise invocation semantics above a hand-authored list of low-level relation rules. The public `INVOCATION_SEMANTIC_MODEL` is now the domain-owned model for target cardinality, argument correspondence, effect projection, obligation meaning, trace policy, and semantic closure. A compiler lowers that model to generic `SemanticJudgmentRuleDefinition` values; the shared relation engine still executes the lowered program.

## Architecture

```text
Semantic knowledge + requested invocation
                  |
                  v
INVOCATION_SEMANTIC_MODEL (upstream contract)
  - evidence presence
  - target identity/cardinality
  - positional argument correspondence
  - result/exception effects
  - typed obligations and reasons
  - trace evidence/ownership policy
  - closure law
                  |
                  v
invocationSemanticModelCompiler
                  |
                  v
Generic SemanticJudgmentRuleDefinition program
                  |
                  v
Generic semantic relation executor
                  |
                  v
Proof-bearing derivations + typed domain projection
                  |
                  v
Authority contract validation
                  |
                  v
Runtime executor -> scanner caller -> downstream
```

## Important changes

- Added `InvocationSemanticModel` and `INVOCATION_SEMANTIC_MODEL` to `invocationSemanticJudgmentInterface.ts`.
- The executable rule catalog is generated by `compileInvocationSemanticModel(INVOCATION_SEMANTIC_MODEL)` instead of being a separately hand-authored low-level rule array.
- Rule trace policy is projected from the model, including evidence selection, obligation ownership, and closure summary.
- Obligation kind and reason are model data; relation witness mapping remains a lowering concern.
- Replaced the `switch` over obligation projection in the algebra with typed projection dispatch. The algebra no longer selects obligation semantics by rule ID.
- Closure now reads the semantic model's closure law.
- Scanner path remains a single `executeAll(semanticKnowledgeDataFlow)` delegation.
